# POWER-LADDER - stage, world bands, protection (enemy-first)

Status: **accepted for implementation 2026-10-28**. This is the foundation module: every other
combat/balance system reads the stage ladder. Enemy design comes first; the player Rune Rank uses
the same 1-100 ladder but its progression detail is deferred.

Bindings: D-065 (ladder/curve), D-066 (data-driven balance), D-067 (KYE2 reference only),
D-064 (DLL-first/Papyrus), ARCHITECTURE.md hard rules 9-10.

## 2. Stage and tier model

Tier index: `tier = min(10, floor((stage - 1) / 10) + 1)`.

Boundary table (computed from the formula):

| Stage | Power | Health x | Damage x | Regen x |
|---:|---:|---:|---:|---:|
| 1 | 1.00 | 1.00 | 1.00 | 1.00 |
| 10 | 1.28 | 1.17 | 1.12 | 1.08 |
| 20 | 1.68 | 1.40 | 1.26 | 1.17 |
| 30 | 2.21 | 1.67 | 1.43 | 1.27 |
| 40 | 2.91 | 2.00 | 1.62 | 1.38 |
| 50 | 3.82 | 2.39 | 1.83 | 1.49 |
| 60 | 5.02 | 2.85 | 2.07 | 1.62 |
| 70 | 6.60 | 3.41 | 2.34 | 1.76 |
| 80 | 8.68 | 4.07 | 2.64 | 1.91 |
| 90 | 11.41 | 4.87 | 2.99 | 2.08 |
| 100 | 15.00 | 5.81 | 3.38 | 2.25 |

The stage is the power budget, not a claim that two actors of the same stage are equal. Base
actor identity, attributes, abilities, equipment and AI remain the actor's own; the stage package
is applied on top within caps.

## 3. Data contracts (the source of truth)

All tables are written by `Runefall.Build`, loaded by `DataStore`, validated before gameplay, and
exposed through `FormCatalog` where records are needed. C++ does not hardcode a tunable value.

| File | Purpose | Required columns |
|---|---|---|
| `stage_ladder.csv` | 100 rows, precomputed curve | stage, tier, powerIndex, healthMult, damageMult, regenMult |
| `tier_definitions.csv` | 10 tiers, names/keywords/ranges | tier, name, stageMin, stageMax, keywordEditorId, description |
| `world_bands.csv` | world/encounter difficulty bands | bandId, sourceType, sourceEditorId, hold, band, priority, notes |
| `stage_variance.csv` | deterministic per-actor jitter | archetype, offsetMin, offsetMax, seedSalt, notes |
| `race_classification.csv` | race -> anatomy/class/family | raceFormKey, plugin, editorId, class, family, hostEligible, protectionEligible, rewardProfile, priority, source, notes |
| `class_taxonomy.csv` | class -> anatomy/intelligence | class, anatomy, intelligence, hostEligible, anomalyType, notes |
| `class_resistance.csv` | class -> resistance multipliers | class, damageKey, multiplier, priority, notes |
| `protection_rules.csv` | tunable protection values | key, value, min, max, notes |
| `penetration_sources.csv` | penetration source rules | sourceType, sourceId, points, stackRule, priority, notes |
| `encounter_classes.csv` | encounter stage/protection policy | class, stageMode, protection, stageOffset, capPerCell, notes |
| `spawn_tables.csv` | reserved for encounter/spawn design | (defined with encounter spec) |
| `form_ids.csv` | generated record identity | editorId, plugin, localFormId, recordType |

Rules:
- A missing or malformed table disables the affected feature with a specific error; it never
  silently substitutes a hardcoded map.
- All numeric values are clamped by `protection_rules.csv`/config min-max and validated for
  NaN/infinity.
- Any new world band, race patch, class, spawn rule or protection tweak is a data change plus a
  validator run, not a C++ edit.
- ESP records are generated from the same data; do not hand-edit generated records.

## 4. ESP contract (engine-required records only)

Generated by `Runefall.Build` from data; identity from `form_ids.csv`:

- **Keywords**: `RF_KW_Tier_01..10`, `RF_KW_Host`, `RF_KW_Anomaly`, `RF_KW_Provisional`,
  `RF_KW_Penetration`, `RF_KW_BypassProtection`, `RF_KW_NoProtection`.
- **GLOB**: config mirrors/state where the engine must read a value (for example existing
  `RF_GLOB_State_RuneTier`); runtime stage profiles are DLL/co-save data, not one GLOB per actor.
- **MGEF/SPEL/PERK**: class-resistance packages and stage-tier packages generated from
  `class_resistance.csv` and `stage_ladder.csv`; no hardcoded magnitudes in the plugin.
- **QUST**: debug/diagnostic host only. No Papyrus gameplay logic (D-064).

If a value can be represented as data loaded by the DLL, it must not be baked into a record or a
script. Record generation exists only where the engine requires a form.

## 5. Race classification and unknown fallback

Resolution order (first hit wins):

1. Actor/ref override keyword (`RF_KW_Host`, `RF_KW_Anomaly`, `RF_KW_NoProtection`).
2. `race_classification.csv` explicit row (FormKey preferred; EditorID fallback).
3. Actor template chain (`TESActorBaseData::baseTemplateForm` -> template NPC/race).
4. Race keywords (`ActorTypeNPC`, `ActorTypeAnimal`, `ActorTypeCreature`,
   `ActorTypeUndead`, `ActorTypeDaedra`, `ActorTypeDragon`, machine equivalents).
5. Race inheritance (`TESRace::armorParentRace` / `morphRace` chain).
6. Conservative heuristic (playable + facegen -> humanoid host; child/immobile -> non-combat).
7. **Provisional host**.

Provisional host policy:
- always gets a stage and a class;
- protection enabled;
- generic family/reward profile `ProvisionalFlesh`;
- one log line per race + entry in `RunefallUnknownRaces.log` (EditorID, plugin, localFormID);
- can be patched by adding a `race_classification.csv` row without touching code;
- config `iUnknownRacePolicy` (default 0 = auto-host; 1 = anomaly; 2 = no protection).

Known defaults (D-065 decision): host = animal/beast/insect/mudcrab/riekling/giant/mammoth/troll/
falmer/spriggan/hagraven/werewolf/werebear; anomaly = dead/skeleton/dragon/dragon priest/Daedra/
dremora/atronach/Dwemer machine/ghost/ash spawn/ash guardian/wisp/wispmother/lurker/seeker/magic
anomaly; vampire = anomaly by default with patch option.

KYE2's parsed race table is a **review seed**; the shipped table is regenerated from vanilla/DLC
masters plus explicit patches. KYE2 classes are not referenced at runtime.

## 6. World bands and stage assignment

`world_bands.csv` is the only source of world difficulty. Source types (priority order):
1. explicit cell/encounter-zone override,
2. location keyword override,
3. hold/region default,
4. global default band.

Stage assignment:
```
baseBand = ResolveWorldBand(ref/cell/location)
stage = clamp(baseBand + archetypeOffset + encounterOffset + seededJitter, 1, 100)
```
- `seededJitter` is deterministic from encounterId/ref FormID + `seedSalt`; no wall-clock.
- Encounter-spawned actors use the encounter's exact stage profile when present.
- Vanilla/ambient actors are untouched by default. Ambient staging is a config/encounter-spec
  decision, off in v1.
- No player-level scaling in the enemy ladder; player level is irrelevant to an enemy's stage.
- Quest-critical/essential/protected actors are excluded unless explicitly overridden.

## 7. Threat protection

Target eligibility:
- target must be `HOST` (including provisional) and `protectionEligible`;
- calculation stack:
```
G  = max(0, targetStage - attackerStage - penetrationPoints)
DR = min(maxReduction, perStage * G)
multiplier = max(1 - DR, damageFloor)
```
- defaults: `perStage = 0.03`, `maxReduction = 0.90`, `damageFloor = 0.05`;
- at gap 10 = 30%, gap 20 = 60%, gap 30+ = 90%;
- protection applies **once** per incoming hit; no perk layer applies the same protection;
- player is not a protected target by default; config toggle may enable it;
- anomalies scale but do not receive host protection; a separate anomaly ladder is reserved;
- bypass/no-protection markers always win;
- unknown/environmental damage has an explicit policy: skip by default, log under trace;
- damage-category coverage (melee, arrows, spells, explosions, poison/DoT, traps, reflected,
  scripted) must be proven by the Phase-1 spike before implementation.

## 8. Player Rune Rank (deferred detail)

- Same 1-100 ladder and tier names; rank is not a biological host stage.
- Attacker effective stage = Rune Rank + equipment penetration (details later).
- No player target protection by default (compatibility-first).
- The player progression spec will reuse `stage_ladder.csv`; it must not fork the ladder values.

## 9. Persistence

Co-save additions (schema v3, migration from v2):
- section 11 `stage_profiles`: encounterId/key -> {stage, tier, class, hostEligible, protectionEligible,
  provisional, source, version, rewardState};
- section 12 `encounter_state`: encounterId -> {active, stage, cellId, spawnedRefs, rewardClaimed,
  createdGameTime, disengagedAt}.
Rules: no raw pointers; validate lengths/keys; unknown/corrupt records dropped with a count;
generic actors without a stored profile recompute deterministically; disabling protection must not
delete profiles.

## 11. Validation gates

1. `stage_ladder.csv` has exactly 100 rows, stages 1-100, tiers 1-10, monotonic multipliers.
2. `tier_definitions.csv` has 10 tiers with the approved names and contiguous ranges.
3. `world_bands.csv` covers every configured hold/location; default fallback exists.
4. Every shipped race classification row resolves; provisional fallback tested with a synthetic
   unknown race and an actor with no template/keyword evidence.
5. Protection table cases: same stage, 10/20/30+ gaps, penetration, cap, floor, bypass,
   player-target default off, anomaly target off.
6. Stage assignment is deterministic across repeated calls/seeds.
7. Co-save round-trip v3; v2 migration; corrupt/large payload rejection.
8. Damage-category coverage matrix from the Phase-1 spike passes.
9. Static gates include the Papyrus policy gate and form_ids coverage; no hardcoded balance
   values in C++ (a repository lint/grep gate should be added with implementation).
10. Optional coexistence test with KYE2, OWL, Worlds Dawn; no dependency.
